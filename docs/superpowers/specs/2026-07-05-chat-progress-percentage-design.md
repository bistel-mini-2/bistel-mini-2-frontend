# 채팅 그래프 진행률 표시 설계

## 목표

채팅 SSE 요청이 실행되는 동안 현재 처리 단계와 진행률을 함께 표시한다. 서버가 보내는 `progress` 이벤트를 진실의 원천으로 사용하되, 단계 사이의 긴 대기 시간에는 실측 시간을 바탕으로 퍼센트를 부드럽게 증가시킨다.

## 실측 기준

2026-07-05 로컬 백엔드에서 각 그래프를 한 번씩 실행했다.

| 그래프 | 전체 시간 | 주요 관찰 |
|---|---:|---|
| recommendation | 29.3초 | 첫 progress 6.4초, `llm_rerank` 12.6초 |
| eligibility | 240초 초과 | `assess_policy` 단계에서 클라이언트 타임아웃 |
| comparison | 8.5초 | 첫 progress 5.9초, 실제 그래프 처리 약 2.5초 |
| policy_summary | 3.1초 | progress 이벤트 없이 완료 |

한 번의 측정값은 절대적인 SLA가 아니라 초기 보간값으로만 사용한다. 서버 이벤트가 도착하면 시간 추정치보다 서버 단계를 우선한다.

## 진행률 계산

- 요청 시작 시 1%에서 시작한다.
- `intent` 이벤트로 그래프 유형을 확인하고 해당 그래프의 실측 프로필을 선택한다.
- `progress.started` 수신 시 이전 단계 완료 퍼센트에서 현재 단계 목표 직전까지 시간 기반으로 증가한다.
- `progress.completed` 수신 시 현재 단계의 완료 퍼센트로 즉시 보정한다.
- `done` 수신 전에는 99%를 넘지 않는다.
- `done` 수신 시 100%로 확정한 뒤 최종 응답으로 교체한다.
- `failed`와 `cancelled`에서는 마지막 퍼센트를 유지하고 기존 오류/취소 문구를 표시한다.
- 이벤트가 없는 `policy_summary`는 전체 실측 시간 3.1초를 기준으로 95%까지 증가하고 완료를 기다린다.
- `eligibility`는 측정이 타임아웃됐으므로 장기 단계에서 감속하는 보수적 프로필을 사용한다. 90% 이후에는 완료 이벤트 전까지 매우 느리게 증가한다.

퍼센트는 절대로 감소하지 않는다. 서버 단계가 시간 추정치보다 뒤에 있더라도 현재 값을 유지하고 다음 서버 이벤트부터 다시 보간한다.

## 데이터 모델과 UI

임시 assistant 메시지에 다음 필드를 추가한다.

- `progressFlow`: 현재 그래프 유형
- `progressStep`: 현재 단계 번호
- `progressTotal`: 전체 단계 수
- `progressStatus`: `started` 또는 `completed`
- `progressPercent`: 화면에 표시할 정수 퍼센트
- `progressStartedAt`: 시간 보간 기준 시각

기존 `RequestStatusMessage` 안에 현재 상태 문구와 `N%`를 같은 줄에 표시하고, 아래에 얇은 진행 바를 렌더링한다. 기존 도담 색상 변수와 컴포넌트 스타일을 유지하며 별도 화면이나 모달은 추가하지 않는다.

## 구성 경계

- 순수 계산 함수는 그래프 프로필 선택, 서버 단계 퍼센트 계산, 시간 보간만 담당한다.
- React 타이머는 진행 중인 assistant 메시지가 있을 때만 250ms 간격으로 실행한다.
- SSE 콜백은 원본 이벤트 값을 메시지 상태에 기록하고 계산 함수에 전달한다.
- 최종 응답, 오류, 취소, unmount 시 타이머가 남지 않아야 한다.

## 예외 처리

- `step` 또는 `total_steps`가 없으면 flow 전체 시간 기반 보간으로 대체한다.
- 알 수 없는 flow는 30초 기본 프로필을 사용한다.
- 잘못된 숫자, 0 이하 total, 역순 이벤트는 현재 퍼센트를 낮추지 않고 무시한다.
- 복구 폴링 중에는 기존 퍼센트에서 최대 95%까지 느리게 증가시키고, 완료 payload 수신 시 100%로 전환한다.

## 검증

- 순수 계산 함수: started/completed/done, 누락 필드, 역순 이벤트, 99% 상한, 단조 증가를 검증한다.
- 컴포넌트: 진행 문구와 퍼센트 및 진행 바가 함께 렌더링되는지 확인한다.
- 흐름: recommendation, eligibility, comparison, policy_summary 이벤트 샘플을 주입해 단계 이동을 검증한다.
- 회귀: 오류·취소·복구·unmount 이후 타이머가 상태를 갱신하지 않는지 확인한다.
- 전체 lint와 production build를 통과해야 한다.
